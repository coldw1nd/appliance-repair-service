# Сервис ремонта бытовой техники

Информационная система для учёта заявок на ремонт бытовой техники. Репозиторий содержит SQL-модель данных, десктопное приложение на JavaFX, REST-бэкенд на Spring Boot и веб-интерфейс.

## Структура

- `src/main/resources/sql/` — схема базы данных и тестовые данные
- `src/main/java/` — десктопное приложение на JavaFX
- `backend/src/main/java/` — REST-бэкенд на Spring Boot
- `backend/src/main/resources/static/` — веб-интерфейс
- `backend/src/main/resources/db/migration/` — миграции Flyway
- `backend/src/test/java/` — тесты бэкенда
- `docker-compose.yml` — контейнеры PostgreSQL и бэкенда

## Модель данных

Таблицы `customers` и `repair_requests`, внешние ключи, ограничения на статусы (`NEW`, `DIAGNOSING`, `REPAIRING`, `COMPLETED`, `CANCELLED`), приоритеты (`LOW`, `MEDIUM`, `HIGH`, `URGENT`) и стоимость, индексы для поиска, набор тестовых данных.

Скрипты применяются автоматически при первом создании контейнера PostgreSQL. Бэкенд расширяет эту схему миграциями Flyway: добавляет пользователей, роли, сессии, справочник типов техники, теги, комментарии и журнал аудита.

## Десктопное приложение

JavaFX 21, FXML, JDBC, Apache POI.

- Список заявок с фильтрацией и сортировкой
- Создание, редактирование, удаление заявок
- Управление клиентами
- Экспорт в Excel

## Бэкенд

Java 21, Spring Boot 3.5, Spring Security, Spring Data JPA, PostgreSQL 16, Flyway, HikariCP, jjwt, BCrypt, Apache Commons CSV, Springdoc OpenAPI.

- Аутентификация по JWT: access-токен на 15 минут, refresh-токен на 14 дней в httpOnly cookie с ротацией при каждом обновлении
- Роли `VIEWER`, `REPAIRER`, `ADMIN` и разграничение доступа на уровне эндпоинтов
- Парольная политика, блокировка аккаунта после пяти неудачных попыток входа, обязательная смена временного пароля
- Миграции Flyway, Hibernate в режиме `validate`
- Оптимистичная блокировка через `@Version` для заявок, пользователей, типов техники и комментариев
- Поиск с ключами (`тип:`, `статус:`, `срочно:`, `стоимость>`) и свободным текстом, динамические запросы через JPA Specifications
- Массовые операции: архив, восстановление, смена статуса, добавление и удаление тега
- Импорт CSV с предпросмотром, режимами `CREATE_ONLY` и `UPSERT_BY_EXTERNAL_ID`, экспортом отфильтрованных заявок
- Расчёт уровня риска в сервисе и в SQL-триггере
- Архивирование вместо удаления, безвозвратное удаление только для администратора с подтверждающим заголовком
- Журнал аудита с correlation ID, IP и user-agent, запись в отдельной транзакции
- Пагинация и сортировка списков
- Swagger UI и Actuator

## Веб-интерфейс

Vanilla JS, HTML, CSS без сборщика и внешних зависимостей. Раздаётся бэкендом как статика.

- Вход, смена пароля, автоматическое обновление access-токена
- Вкладки: заявки, аналитика, типы техники, пользователи, журнал аудита
- Таблицы с сортировкой, пагинацией и множественным выбором
- Модальные окна создания и редактирования, диалоги подтверждения
- Импорт и экспорт CSV, всплывающие уведомления об ошибках

## Тесты

JUnit 5, AssertJ, H2.

- Unit-тесты калькулятора рисков и парсера поисковых запросов
- Smoke-тест загрузки контекста Spring
- Тестовый профиль `application-test.yml`: H2 в памяти, Flyway отключён, схема создаётся Hibernate в режиме `create-drop`

## Требования

- Docker и Docker Compose
- JDK 21 и Maven 3.9+ — для десктопного приложения, тестов и запуска бэкенда вне контейнера

## Настройка окружения

Файл `.env` в корне проекта не хранится в репозитории. Создайте его перед первым запуском:

```env
POSTGRES_DB=appliance_repair_service
POSTGRES_USER=appliance_app
POSTGRES_PASSWORD=<пароль базы данных>
POSTGRES_PORT=5434

APP_PORT=8080
COOKIE_SECURE=false
PERMANENT_DELETE_ENABLED=true

JWT_SECRET_BASE64=<base64-строка не короче 32 байт>
JWT_ISSUER=appliance-repair

BOOTSTRAP_ADMIN_EMAIL=<email администратора>
BOOTSTRAP_ADMIN_PASSWORD=<временный пароль администратора>
```

Секрет для JWT можно сгенерировать командой `openssl rand -base64 32`.

Администратор создаётся при первом старте, если таблица пользователей пуста. Пароль помечается как временный, система потребует заменить его при первом входе.

## Запуск бэкенда и веб-интерфейса

Из корня проекта:

```bash
docker compose up -d --wait --wait-timeout 420
```

Первый запуск занимает несколько минут: Maven внутри контейнера скачивает зависимости и собирает приложение.

После старта доступно:

- Веб-интерфейс — http://localhost:8080/
- Swagger UI — http://localhost:8080/swagger-ui.html (только для роли `ADMIN`)
- Health-check — http://localhost:8080/actuator/health
- PostgreSQL — localhost:5434

Логи бэкенда:

```bash
docker compose logs -f backend
```

Запуск бэкенда вне Docker требует поднятой базы и переменных окружения из `.env`, экспортированных в shell:

```bash
docker compose up -d postgres
cd backend
mvn spring-boot:run
```

## Запуск десктопного приложения

База должна быть доступна на порту 5434:

```bash
docker compose up -d postgres
```

Затем из корня проекта:

```bash
mvn javafx:run
```

## Запуск тестов

```bash
cd backend
mvn test
```

Тесты используют H2 в памяти и не требуют Docker или запущенного PostgreSQL.

## Остановка

```bash
docker compose down
```

Volume с данными сохраняется. Чтобы удалить контейнеры вместе с базой:

```bash
docker compose down -v
```
